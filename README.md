# Knowledge base pipeline

Собирает базу знаний поддержки из обращений с помощью GigaChat, чинит плохие
базы и сливает базы между собой. На входе и на выходе — Excel.

## Что умеет

| Команда | Что делает |
|---|---|
| `make run CONFIG=...` | вливает дамп обращений в базу; первый дамп создаёт базу |
| `make merge-base CONFIG=...` | вливает в базу другую хорошую базу |
| `make repair-base CONFIG=...` | делает из плохой базы хорошую (новую, отдельную) |
| `make dedupe-base CONFIG=...` | убирает дубли внутри базы |
| `make inspect CONFIG=...` | показывает колонки входного файла и проверяет модели |
| `make models` | показывает модели, доступные по каждому сертификату |

Плохую базу сразу в живую не вливают: сначала `repair-base`, потом
`merge-base` с её результатом.

## Подготовка

1. `cp .env.example .env`, заполнить `PYTHON` и `SBEROSC_TOKEN`.
2. Положить сертификаты в `.certs/`: `glm.pem`, `glm.key` — чат-модель;
   `gigachat.pem`, `gigachat.key` — эмбеддинги.
3. `make setup`.
4. `make models` — убедиться, что оба сертификата видят свои модели.

## Excel базы можно править

Перед каждым `run`, `merge-base` и `dedupe-base` самый свежий Excel базы
читается обратно. Поэтому:

- удалили строку — она не вернётся со следующим дампом;
- поправили вопрос, ответ или категорию — правка останется;
- стёрли причину в «Почему спорная» — запись считается подтверждённой.

Править нужно именно последний файл базы (с самой поздней датой).

## Спорные записи

Если обращение не прошло одну из проверок фильтра (вопрос разовый, ответ
разовый или неполный), оно не отбрасывается, а попадает в базу жёлтой строкой
с причиной в колонке «Почему спорная». Не прошло две и больше — отбрасывается.
Если та же запись пришла из другого обращения, жёлтая пометка снимается.

## Конфиги

Конфиги лежат в `configs/`, у каждой команды свой:

- `supplier-portal-sap.toml` — `make run`: база, путь к дампу и его колонки;
- `supplier-portal-sap-merge.toml` — `make merge-base`: база и путь к
  хорошей базе;
- `supplier-portal-sap-dedupe.toml` — `make dedupe-base`;
- `make repair-base` — свой конфиг на каждую плохую базу, пример ниже.

Общие поля во всех конфигах:

- `name` — название базы. По нему база и находится, имя дампа неважно: новый
  дамп — новый путь в `[dump].path`, база та же;
- `output_dir` — папка баз;
- `[domain]` — чья это поддержка и список категорий.

`merge_strategy` задаёт, что делать, если новая запись называет другую
причину проблемы, уже описанной в базе: `accumulate` — оставить обе списком,
`replace` — оставить новую.

Конфиг починки устроен так же, только вместо `[dump]` — `[input]` (колонки
сверьте через `make inspect`):

```toml
name = "Моя база"
output_dir = "/Users/19480633/Desktop/Базы знаний/Готовые базы"

[input]
path = "/Users/19480633/Desktop/Плохая база.xlsx"
question_columns = ["Вопрос"]
answer_columns = ["Ответ"]

[domain]
name = "Центра снабжения и офисных сервисов"

[domain.categories]
how_to = "как выполнить действие: где найти, как создать, изменить, настроить"
# ...
```

Модель, сертификаты, число потоков, пороги и лимиты — в `config.py`.

## Во время прогона

- Прогон идёт часами. Мак не уснёт, команды запускаются под `caffeinate`.
- Ctrl+C останавливает прогон. Та же команда продолжит с места остановки.
- В терминале видно прогресс и строки, где что-то пошло не так. В конце —
  сводка вызовов модели и путь к лог-файлу с ошибками.
- Запросы идут по одному (`WORKER_COUNT = 1`). Для скорости можно увеличить,
  пока GigaChat не начнёт отвечать 429.
- Чтобы прогнать всё заново (например, после правки промптов), поставьте
  `FORCE_REPROCESS = True` в `config.py`, а после верните `False`.

## Как это работает внутри

Для пополнения базы из дампа:

1. **Отбор и переписывание.** Модель оценивает каждое обращение и переписывает
   пару в короткий вопрос и ответ. Имена заменяются ролями, номера заявок
   убираются.
2. **Дубли внутри дампа** схлопываются: одинаковые ответы — в один, разные
   причины одной проблемы — в список.
3. **Вливание в базу**: новая запись дополняет или заменяет совпавшую.

Код проверяет каждую запись модели: все числа и ссылки ответа должны быть в
исходном тексте. Ссылки модель вообще не пишет — код подставляет их сам.

Подробно об устройстве кода — в [AGENTS.md](AGENTS.md).
